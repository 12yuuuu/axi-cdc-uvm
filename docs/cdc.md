# Structural CDC check

Generated by `tools/cdc_check.py` (Yosys + slang netlist, flat, word-level). Every flop, memory port and output is assigned the domain of its clock; every input is followed back through combinational logic. Each crossing must be a synchronizer chain (SYNC), a dual-clock memory (MEM) or a FIFO read multiplexer selected from the reading domain (MUX); anything else is a violation.

Safety arguments for the structures that a netlist alone cannot prove:

- **Multi-bit SYNC groups** are the gray-coded FIFO pointers (one group per pointer). Only one bit may change per update; `SVA_GRAY` checks this on every pointer in every simulation run (0 fires in the regression, and `neg_ptr_glitch` shows it fires).
- **MEM / MUX**: an entry is written only while the synchronized read pointer shows it free and read only after the synchronized write pointer shows it written, so the data is stable for at least two destination cycles before it is used. `SVA_MOVE`, `SVA_OCC` and the data check cover this protocol in simulation.
- Metastability itself (MTBF) and the timing of the crossing nets are outside a netlist check: they need the synchronizer constraints in static timing analysis.
